## Реализовано
Этап 1: отсутствующий winsetup.toml создаётся из model::defaults() с тремя встроенными профилями. persist_noclobber исключает замену существующего файла, включая гонку создания. Диск — D:, если существует, иначе SystemDrive (резерв C:). В интерфейсе есть уведомление и ручная починка отсутствующего конфига. Проверки конфига, работающего winget --version (PATH и WindowsApps), локального Connectivity=4, администратора и места имеют единый формат. Предпросмотр и главная показывают подготовку среды без скачивания.
Этап 2: отдельная подтверждаемая установка winget и согласие в общем подтверждении профиля, включая автоматический режим. Задачи winget/msstore при отсутствии работающего winget получают «ожидает winget» и пропускаются; итоговая проверка не объявляет их неудачными установками. Остальные операции сохраняют свою логику и существующие проверки прав/места/точки восстановления. При продолжении подготовка проверяется заново. Инструкция Microsoft Store показывается одним диалогом за сессию и остаётся в блоке готовности; доступна кнопка «Проверить снова».
Один новый безопасный devtest «Подготовка среды» только читает конфиг и запускает winget --version. Существующий match порядка этапов дополнен новым Action::Bootstrap для компиляции.

## Разрешённые домены и ограничения
В коде фиксированы: aka.ms, github.com, release-assets.githubusercontent.com, objects.githubusercontent.com, download.microsoft.com.
github.com ограничен путями /microsoft/winget-cli/releases/ и /microsoft/microsoft-ui-xaml/releases/. aka.ms ограничен /getwinget и /Microsoft.VCLibs.x64.14.00.Desktop.appx. Реальные исходные ссылки закреплены на перечисленных релизах GitHub; ака.ms — проверенный официальный указатель, для загрузки закреплённой версии не используется. Остальные домены разрешены как CDN редиректов. Поддомены по маске, чужие репозитории, URL с логином/паролем, HTTP и нестандартные порты отвергаются.
На файл: максимум 3 редиректа, соединение 15 секунд, запрос 300 секунд. Лимиты: bundle 320 МиБ, ZIP 128 МиБ, Xaml 32 МиБ. SHA-256 всех трёх файлов закреплены в коде. Распаковка: до 256 записей ZIP, до 8 подходящих APPX/MSIX, до 64 МиБ на зависимость и 128 МиБ суммарно; пути наружу запрещены.
Перед установкой каждого APPX/MSIX проверяются Valid Authenticode и имя подписанта Microsoft Corporation; несовпавший файл удаляется, установка запрещается. ZIP проверяется SHA-256, подписанные пакеты внутри — Authenticode. Установка только Add-AppxPackage -DependencyPath для текущего пользователя. Скачанные EXE/MSI не исполняются.

## Допущения и ограничения
- Windows 10 x64 с работающими PowerShell/Appx и WebView2 для запуска самого Tauri. Установка WebView2 не входит в задачу. Версия winget закреплена, автоматического выбора будущих релизов нет; изменение официального файла приведёт к отказу по SHA-256.
- Штатная папка загрузок: %TEMP%\winsetup-winget\run-<случайное имя>. Очистка вызывается после успеха, ошибок и обработанной паники; чужое содержимое базовой папки не удаляется. Блокировка файлов Windows приводит к явной ошибке очистки. Принудительное завершение приложения/питания не гарантирует очистку.
- Тайм-аут PowerShell установки — 300 секунд; служба развёртывания Windows может завершить уже начатую операцию после прекращения ожидания. Установка App Installer не откатывается автоматически; используется повторная проверка и инструкция Store.
- PATH пополняется только в текущем процессе, чтобы существующий engine::install нашёл обнаруженный WindowsApps alias. Системный PATH и реестр не меняются.
- Дефицит места, отсутствие интернета и прав не исправляются автоматически. Существующие ограничения выполнения профиля сохранены.
